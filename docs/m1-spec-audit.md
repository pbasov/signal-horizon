# M1 Build vs. Mechanics Spec — Brutally Honest Gap Report

## 1. Headline: how faithful is the build, really?

The build is a **faithful simulation core wrapped around a hollow game**. The pure, deterministic, replay-folded sim layer is genuinely well-engineered — the contract struct, the per-tick serve-or-breach heartbeat, the one-axis-at-a-time teaching mask, the escalation→re-tame engine, the fault spectrum's architecture, the consequence-math (`previewLaunch`), the empirical phasing assist, and the truthful loss-stamp/diagnose trace all exist as honest, tested code. But the build does **not** match the spec where the spec actually lives: in *interaction and visualization*. The launch planner is confirmed to be the vending machine you already caught — a 3-button preset menu with a text readout, and the entire §3.1 "drag altitude/inclination/phase/RAAN" ceiling is absent end-to-end (RAAN isn't even in the data model). The §1 composable satellite atom is not built (one hardcoded smallsat, one BROADCAST antenna whose `type` is decorative, loadout discarded at commit). §7's per-class routing — the whole "demand-shape produces topology-shape" thesis — is inert because no traffic classes exist and every contract carries identical lat-only weights. §4.3 oversubscription is a deterministic capacity cliff, not statistical multiplexing (load is monotone, never bursty). And the §5 telegraphed fault — the signature M1 "telegraphed event" — is *functionally dead*: a session-ordering bug deletes the fault before the router ever sees it, then spuriously reports "RECOVERED." Worst of all for a game whose GDD calls visualization "the survival condition": **the network is invisible for Acts 3a/3b** — no link line is ever drawn region→sat→ground, no congestion coloring, no path-on-globe trace. The spec's defining loop — drag the orbit, watch the coverage-gap overlay shrink on the globe — is missing on both the input side and the render side. So: the brain is real; the body the brain is supposed to drive is largely not there. Roughly half the make-or-break visualization (Acts 1, 2, 4) lands; the half that carries the back of the hour does not.

## 3. Faithful parts — credit where due

These are genuinely well-built and should not be touched in remediation except to wire them to a UI:

- **Determinism / replay / golden discipline.** The sim layer is pure, seeded, replay-folded throughout (router, faults, escalation). The escalation→re-tame loop is demonstrated **end-to-end in `net-replay.test.ts`** (corridor grows → bandwidth axis flips → dips past near-breach grace → re-tames via parallel LEO + prefer override). This is the porting/golden discipline working as intended.
- **The Contract struct + the one-axis-at-a-time mask architecture** (`contract.ts`, `scenario.ts`). Complete 3-axis SLA shape; adding an axis is a one-line `activeAxes` change. Clean and faithful to §4.1.
- **Per-tick serve-or-breach heartbeat** (`session.ts servedFractionFor`, `router.ts solve`): all-axes-must-hold AND, availability-as-most-common-breach, shared m2 `BREACH_GRACE_SECONDS`. Faithful to §4.2.
- **The rolling-window availability fix** (`availability.ts`) for the LEO sawtooth — a genuinely thoughtful piece of modeling.
- **The consequence math `previewLaunch`** (`world.ts:338`): truthful ground track, period, per-contract latency floor, covered fraction, binding constraint — uses the *same* router/link-budget as commit. The brain is right; it's just wired to text.
- **The empirical phasing assist `suggestPhasing`** (`phasing.ts:143`): measures zero-gap N across 16 probe phases, deliberately returns `zeroGapN−1` — viable-but-imperfect by construction. Faithful to §3.3.
- **The batch-launch mechanism** (`apply-action.ts:83`): one action → N evenly-phased sats in a plane via `count + phaseSpreadRad`. Correct §3.4 plumbing.
- **§2 GEO/LEO motion contrast** (`world.ts`): GEO parks by construction (n==ω), LEO sweeps/sets — physically honest. The one genuinely faithful §2 piece.
- **The event-driven re-solve split** (`router.ts:509 resolveTick`): full search only on topology-key change, cheap re-eval otherwise. Faithful to §7.1's "not every tick."
- **The fault sim architecture** (`fault-types.ts`/`fault.ts`/`trace.ts`): four-kind spectrum, causal-vs-rare-random as distinct streams, rare-random floor (1e-6/s), degradation-as-haircut. Not a stub — structurally faithful to §5.
- **The self-diagnosing `diagnose()` + loss-stamp** (`trace.ts`): rich binding-constraint/kind-of-fix for all 4 axes + SPOF + over-provision, and the §7.5 `LinkLossStamp{aId,bId,cause,atS}` with geometric cause + sim-time. The data seed is honestly planted.
- **The curriculum scaffold** (`scenario.ts`): state-gated (not clock-timed), one-concept-per-act, the 3a/3b fault fence with a belt-and-braces emit-time assert, the deliberate Act-4 "to be continued" stop. The strongest single artifact in the build.
- **Acts 1, 2, 4 visualization** (`orrery.ts`): region lights signal-green when served; Act-2 sweeping footprint discs + live availability sawtooth strip; Act-4 signal visibly crawls Earth→Mars at real light delay with a freshness-desaturating data node + cache-placement freshness jump. These three acts deliver their concept by sight, as the spec demands.

## 4. Remediation priority order

Ordered to convert "faithful sim, hollow game" into "build matches spec" with least wasted motion. The first three are the ones that make the build *not a vending machine*; they reuse the already-faithful sim brains, so they are mostly UI/render wiring, not new sim.

**P0 — Make the launch planner the §3.2 instrument it is supposed to be.** This is the catch you already made, and it's the single highest-leverage fix because the truthful math already exists.
1. Add editable orbit parameters — **altitude and inclination first** (§3.1's named first two) — as drag/slider inputs in `net-planner.ts` + `main.ts` keydown, mutating a draft, not just cycling presets. Add `raanRad` to the `net_launch` wire (`action.ts:96`) and `resolveOrbit` (`world.ts:158`); phase already exists.
2. Add preview render slices to `NetRenderState` (`orrery.ts:165`): the draft **ground track**, draft **footprint**, and the **contract coverage-gap overlay**. Feed `previewLaunch`'s already-computed `groundTrack`/`coveredFraction` (`world.ts:338`) — currently computed and thrown away — into the orrery so the consequence updates *on the globe as you drag*.
3. **Charge for launches.** `applyNetAction` should return the real `launchDraftCost` and `session.launchSat` must debit `this.balance` (`apply-action.ts:99`, `session.ts:434`). The formula already exists; it's a one-line wire. Add a flat launch-failure risk roll off the already-seeded RNG (the §3.5 minimum).

**P1 — Draw the network. (GDD §5 survival condition; carries Acts 3a/3b.)** Render the region→sat→ground link line in net mode on the orrery (it currently draws nothing but the Act-4 Mars crawler). Color links by utilization/headroom so oversubscription and near-breach are visible *before* breach. Animate the re-route when a link drops. Surface the trace as a first-class path-on-globe ("mtr") view, and surface `renderLossStamp` (currently dead code) — the §7.5 predictability seed the spec calls REQUIRED-in-M1. This is render work against data the sim already produces.

**P2 — Fix the telegraphed-fault session-ordering bug.** In `session.ts`, `downSatIds` must read the fault *before* `rollAndApplyFaults` resolves/deletes it at `failsAtS` (`session.ts:960`/`758`). Right now the signature M1 telegraphed event drops nothing and spuriously prints "RECOVERED." Small, surgical, and it makes the §5 watch-and-act loop real. While here: add a live ticking countdown (not a one-shot log line), and instantiate a `transient` fault in a scenario script (the type is built, never fired). Re-scale `LOW_ORBIT_REF_M` to the toy world so "a LEO faults more than a GEO" actually registers.

**P3 — Wire the per-contract prefer control + traffic classes (§7.2/§7.3 ceiling).** Surface `net_set_prefer` (currently test-only) as the prefer-latency↔bandwidth↔stability slider — §10 calls it "the first thing the player tunes." Introduce a traffic-class concept so contracts carry differentiated weights; today every contract is `{lat:1,bw:0,stab:0}`, so the cost-blend's `w_bw` never bites and "demand-shape → topology-shape" is inert. This unlocks the §7.4 interactive diagnostic view (drain *all* shortfalls into a panel, not just `shortfalls[0]`).

**P4 — Make oversubscription stochastic (§4.3).** Replace the monotone `escalateLoad` ceiling with a time-varying/bursty `offeredLoad` (diurnal/noise term with non-coincident peaks across contracts), and make the bandwidth evaluator read the contract's own `slaBandwidth` (currently dead data) instead of the uniform sat-side capacity constant (`session.ts:890`, `router.ts:370`). This turns the deterministic capacity cliff into the statistical-multiplexing bet the spec's early-game tension depends on. Depends on P1 (the load visualization) to be felt.

**P5 — Composable satellite atom + relay topology (§1/§7.1), largest scope, defer last.** Build bus tiers 2–4 with real slot counts, make `AntennaType` behavioral (BROADCAST asymmetry, GATEWAY downlink), and add CROSSLINK/LASER sat-to-sat edges so `solve()` has a multi-hop graph to actually find a shortest path through. This is the most genuinely-missing-from-scope (and the build's own design doc arguably scopes Act 1 to one smallsat), so it is correctly last — but until it exists, "shortest-path solver," "emergent roles," and "the connectivity puzzle" remain structurally hollow.

A note on scope honesty: a few gaps above (MEO/Molniya, hard faults, full power-user terminal, bus tiers 2–4) are plausibly "deferred by Act-1 scope" per the build's own `docs/signal-horizon-m1-design.md`. But against the **mechanics spec** being audited, P0–P2 are not deferrable — they are the mechanics the spec calls LOCKED and the gate is explicitly designed to catch, and they are mostly wiring against sim code that is already faithful.
